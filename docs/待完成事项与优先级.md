## 1. 当前状态概述

当前版本已经完成配置加载、播放源管理、首页、分类、搜索、详情、多线路播放、收藏、历史、内置播放器、CatVod 本地服务、Profile 加密、来源质量管理和多网盘应用内登录基础能力。

多网盘第一阶段已经接入：

- 夸克网盘；
- UC 网盘（Cookie / TV Token 两种扫码方式）；
- 百度网盘；
- 115 网盘；
- 天翼云盘；
- 移动云盘。

当前代码已通过 TypeScript 类型检查、275 项完整自动化测试和生产构建。核心修复 Electron E2E 13/13、CatVod 生命周期 E2E 14/14、数据库损坏恢复 E2E 5/5、安全审计 21/21 均通过；x64 目录测试包已使用最新代码重新生成。六种网盘真实扫码和破坏性凭据清除、真实第三方网盘深层目录及 arm64 实机仍属于环境依赖验收。

后续工作不再以“继续扩大播放源规则数量”为主，而是优先解决真实使用闭环、异常恢复、安装发布和核心体验问题。

---

## 2. 优先级定义

| 优先级 | 定义 | 处理原则 |
|---|---|---|
| P0 | 当前版本发布和真实使用前必须完成 | 未完成前不建议将当前版本作为稳定版本对外使用 |
| P1 | 核心体验增强和正式发布能力 | P0 稳定后按顺序实施 |
| P2 | 独立产品能力扩展 | 不混入当前点播和网盘闭环 |
| 暂缓/不做 | 不进入近期计划或明确不再实施 | 保留已有代码，不继续主动扩展 |

## P0-02　补齐网盘账号管理【代码与受控 E2E 已完成，真实账号待验收】

### 当前问题

已完成标准化状态区分、UC 凭据模式、单网盘清除、多网盘任务隔离、错误 Provider 轮询阻断、未知任务拒绝，以及退出应用仅取消未完成二维码任务并保留已登录凭据。账号专项和 Electron E2E 已通过；仍需在测试账号环境验证六种真实网盘扫码和清除后的服务端状态。

### 待完成事项

1. 使用真实账号验证“清除凭据”入口；
2. 清除单个网盘对应的 Cookie、Token 或账号凭据后刷新状态；
3. 评估是否增加二次确认，避免误操作；
4. 继续细化以下状态：
   - 未登录；
   - 已登录；
   - 登录已失效；
   - 状态检查失败；
   - 本地服务未启动；
5. UC 显示当前使用 Cookie 还是 TV Token；
6. 登录失败后提供重新登录、刷新状态和切换来源操作；
7. 清除账号后立即刷新播放能力，不残留旧登录状态；
8. 多个网盘登录任务相互隔离，关闭一个任务不能影响其他网盘。

### 验收标准

- 用户可以只清除指定网盘，不影响其他网盘；
- 清除后再次播放对应网盘内容会正确要求登录；
- Renderer 无法读取明文凭据；
- 各状态文案与实际状态一致。

# 6. 明确不做或近期暂缓的范围

## 6.1 不再继续开发新的 Spider 能力

以下事项不再列入项目后续开发计划：

- Python Spider/Sidecar；
- 新增其他 Spider 运行时；
- 为兼容单个源继续扩大 Spider 宿主 API；
- 以运行更多 Spider 为目标的大规模兼容开发。

现有已经实现的 JavaScript、Drpy、XYQ、XBPQ、CatOpen 等能力继续保留。仅处理影响现有核心功能的明确缺陷和安全问题，不再主动扩展能力边界。

## 6.2 Android Spider 暂不实施

以下事项暂不实施，也不进入近期排期：

- Android Dex/JAR Spider 直接执行；
- Android Runtime Bridge；
- 为 Android Spider 建设独立执行环境；
- 批量开发 Android-only Spider 的桌面替代实现。

现有行为保持为：准确识别、明确提示不兼容、避免误执行。已有替代 Provider 注册表基础设施保留，但不以扩充默认映射为近期目标。

## 6.3 规则兼容样本扩充近期暂缓

近期不再安排：

- 扩大 Drpy、XYQ、XBPQ、CatOpen、Alist 在线样本数量；
- 为单个失败站点补充专用加密或验证码；
- 持续寻找公开稳定 T4 服务；
- 以兼容率数字为目标的规则样本扩张。

现有自动化回归样本继续保留。若现有核心用户配置出现明确回归，只按实际问题进行修复，不启动大范围兼容专项。
