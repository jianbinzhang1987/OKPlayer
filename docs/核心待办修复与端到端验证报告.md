# 2. 网盘凭据、状态区分与任务隔离

## 2.1 已修复问题

### 标准化账号状态

网盘状态不再只依赖 `configured/login` 两个布尔值，新增标准状态：

- `connected`：已登录；
- `expired`：凭据存在但登录失效；
- `not-configured`：未配置凭据；
- `unavailable`：状态接口、本地服务或网络检查失败。

页面能够分别显示：

- 已登录；
- 登录已失效；
- 未登录；
- 状态检查失败。

状态接口失败时保留上一次成功读取到的配置和凭据模式，仅将本次检查标记为不可用，避免网络瞬时故障导致页面误显示为“未登录”。

### UC 凭据模式

新增凭据模式识别：

- Cookie；
- TV Token；
- 扫码授权；
- 账号密码；
- 未识别。

UC 网盘能够明确显示当前使用 Cookie 或 TV Token。

### 多网盘登录任务隔离

登录任务现在同时维护：

```text
taskId → loginProvider
loginProvider → activeTaskId
```

修复内容：

1. 错误 Provider 轮询其他网盘任务时，在主进程直接拒绝；
2. 取消夸克任务不会影响百度、UC 等其他任务；
3. 同一登录方式重复生成二维码时，旧任务先取消，新任务成为唯一活动任务；
4. 成功、过期、失败和取消后立即删除活动任务；
5. 未知任务不再默认归属夸克；
6. 清除账号时只处理该账号相关任务，不影响其他网盘。

### 清除单网盘凭据

清除指定网盘后：

- 仅目标网盘变为未配置；
- 其他网盘登录状态保持不变；
- 页面立即刷新；
- 再次播放该网盘内容会重新进入鉴权流程；
- Renderer 无法读取明文 Cookie 或 Token。

### 应用退出行为

应用退出时只取消尚未完成的二维码登录任务，**不会清除已经保存的 Cookie、Token 或其他网盘凭据**。

```text
退出应用
→ 取消等待中的二维码任务
→ 保留加密 Profile 中的有效凭据
→ 下次启动继续使用已登录状态
```

代码和测试均明确禁止退出流程调用 `/account/clear`。

## 2.2 验证结果

- 账号服务与 Renderer 专项：12 / 12 通过；
- 核心 Electron E2E 中账号相关用例：4 / 4 通过；
- CatVod Profile 加密、服务重启和应用重启恢复：通过；

# 3. 真实代理媒体 Range、拖动与动态端口

## 3.1 已修复问题

### 连续 Range 和拖动

使用真实本地 HTTP 媒体 Fixture 验证：

- `HEAD` 探测；
- `bytes=100-199`；
- `bytes=700-799`；
- Electron `<video>` 实际 `bytes=0-` 请求；
- 播放过程中修改 `currentTime` 完成拖动。

主进程正确透传：

- Range；
- Cookie；
- Referer；
- User-Agent；
- If-Range 等条件请求头。

不同播放会话的 Cookie 不会串用，Renderer 播放 URL 中不包含凭据。

### HLS 子资源

真实本地 Fixture 覆盖：

- 主清单；
- 子清单；
- AES Key；
- TS 分片；
- 字幕地址。

所有子资源均重写为 `fongmi-media://` 受控地址。

### 动态端口

原实现把 CatVod 旧端口固化在播放会话资源中。服务重启后，即使 CatVod 已切换到新端口，旧会话仍可能请求失效端口。

修复后，每次媒体请求都会：

```text
播放会话中的旧本机 URL
→ 获取当前 CatVod baseUrl
→ 替换为当前动态端口
→ 再向上游请求
```

真实 HTTP 测试完成端口 A 关闭、端口 B 启动、同一播放会话继续请求的验证。

### 网盘鉴权错误

网盘媒体探测返回 401/403 时：

- 转换为 `AUTH_EXPIRED`；
- 不再进入网页嗅探掩盖问题；
- 不降低或封禁播放源；
- Renderer 打开对应网盘登录入口。

## 3.2 验证结果

- 媒体协议、播放服务和真实 HTTP Fixture 专项全部通过；
- 核心 Electron E2E 完成实际 MP4 播放、Range、拖动、字幕和弹幕加载；
- CatVod 生命周期 E2E 完成端口变更和服务重启验证。

- 新动态端口分配成功；

## 4.3 SQLite 备份与恢复

### 正常关闭备份

文件数据库正常关闭时：

1. 执行 WAL checkpoint；
2. 校验 `PRAGMA quick_check`；
3. 生成备份；
4. 只保留最近 3 份。

备份目录：

```text
fongmi-desktop.sqlite.backups/
```

### 主库损坏恢复

启动时执行 `PRAGMA quick_check`。检测到损坏后：

1. 原主库归档为 `fongmi-desktop.sqlite.corrupt-<timestamp>`；
2. WAL/SHM 文件一并归档或清理；
3. 从最近有效备份恢复；
4. 恢复配置、设置、收藏、历史；
5. 在设置页展示恢复提示。

如果主库和全部备份均不可用：

- 保留损坏文件；
- 创建新的空数据库；
- 明确显示“无可用备份”；
- 不静默删除或覆盖原文件。

## 4.4 真实打包应用 E2E

完整执行：

```text
写入设置、收藏、历史
→ 正常退出生成备份
→ 人为将主库替换为非 SQLite 文本
→ 再次启动打包应用
→ 归档损坏文件
→ 从备份恢复
→ 页面显示恢复提示
```

结果：5 / 5 通过。

# 5. 网盘深层目录与高级文件管理

## 5.1 已修复问题

### 网盘片库保留 folder/file

原片库媒体过滤逻辑会统一移除 `folder`，导致网盘根目录中的文件夹根本无法显示。

修复后：

- 普通影视来源继续过滤 folder/action；
- `contentType=pan` 的网盘来源保留 folder/file；
- action、live、discovery 仍不进入网盘文件列表。

### 深层目录

已支持：

- 三级及更多目录进入；
- 完整面包屑；
- 点击中间面包屑截断后续路径；
- 返回上一级；
- 返回片库根目录；
- 空目录提示。

### 分页

目录接口支持：

- `page/pageCount/hasMore`；
- 加载下一页；
- 结果追加；
- 去重；
- 保留路径、筛选和目录上下文。

### 搜索、排序和文件类型

当前目录工具栏支持：

- 搜索当前目录；
- 来源默认；
- 名称升序；
- 名称降序；
- 按类型；
- 文件夹优先。

文件类型区分：

- 文件夹；
- 视频；
- 字幕；
- 音频；
- 其他文件。

字幕文件不会被误当作影片详情打开。

### 登录失效恢复

深层目录加载出现鉴权错误时：

1. 保存当前目录和面包屑；
2. 识别对应网盘；
3. 打开登录窗口；
4. 登录成功后自动重新打开原目录。
