# 播放源管理测试用例

更新时间：2026-07-26

## 测试目标

验证播放源配置的新增、更新、切换、重命名、删除、状态识别、异常恢复和持久化，重点排查以下问题：

- 页面显示“正常”，但源实际不可访问。
- 配置导入、切换或检测后页面卡住。
- 配置数量、正常/异常数量与实际列表不一致。
- 当前配置无法管理，或者删除确认失效。
- 配置更新后状态、名称和站点列表不同步。
- 应用重启后配置丢失或当前配置错误。
- `urls` 多仓索引无法导入、只导入一个子配置，或子配置名称丢失。
- 多仓中部分线路失效时导致整仓导入失败。
- 多个配置包含相同 `siteKey` 时搜索结果串源。

## 自动化测试数据

测试使用独立临时用户目录和本地 HTTP 服务，不修改用户现有配置。

| 数据 | 内容 |
|---|---|
| 配置 A | 1 个正常 HTTP 播放源 |
| 配置 B | 1 个正常 HTTP 播放源 + 1 个 Android Dex 不兼容源 |
| 故障配置 | 配置文件可读取，但内容 API 固定返回 HTTP 503 |
| 非法配置 | 返回无法解析的 JSON |
| 慢配置 | 延迟返回，用于检查加载状态能否恢复 |

## 用例清单

| 编号 | 优先级 | 场景 | 操作 | 预期结果 |
|---|---:|---|---|---|
| PS-001 | P0 | 空状态 | 使用全新用户目录启动应用，进入“播放源” | 显示“暂无可用配置”，全部/正常/异常数量均为 0，无控制台异常 |
| PS-002 | P0 | 新增有效配置 | 导入配置 A | 配置 A 成为当前配置，站点总数 1、正常 1、异常 0，页面不持续显示加载状态 |
| PS-003 | P1 | 重复导入同一地址 | 使用新名称再次导入配置 A | 不产生重复配置；原记录名称更新；仍只有 1 条配置记录 |
| PS-004 | P0 | 多配置切换 | 导入配置 B，再切回配置 A | 当前配置、站点列表和顶部播放源选择器同步变化，不混入上一个配置的数据 |
| PS-005 | P0 | 正常/异常筛选 | 配置 B 下分别点击“全部”“正常”“异常” | 数量与实际行数一致；正常列表只显示兼容源，异常列表只显示 Dex 源 |
| PS-006 | P1 | 重命名非当前配置 | 重命名配置 A | 名称立即更新，切换后当前配置名称与新名称一致，重启后仍保留 |
| PS-007 | P0 | 删除二次确认 | 对非当前配置第一次点击删除，再次点击确认 | 第一次不删除且按钮提示改变；第二次删除；配置和站点数据不残留 |
| PS-008 | P0 | 当前配置管理 | 查看当前配置卡片 | 当前配置应具备重命名和删除入口，或“管理配置”能进入包含当前配置的管理列表 |
| PS-009 | P0 | 非法配置恢复 | 导入非法 JSON | 显示明确错误；保持原当前配置；按钮恢复可点击；页面无永久 loading |
| PS-010 | P1 | 慢配置加载 | 导入延迟配置 | 加载期间显示“正在添加”，请求完成后恢复；不会重复提交或永久卡住 |
| PS-011 | P0 | 实际不可访问源识别 | 导入“配置可读、内容 API 返回 503”的故障配置 | 当前卡片和源状态应显示异常/不可用，而不是“正常/内容获取正常” |
| PS-012 | P0 | 重新检测有效性 | 故障配置下点击“重新检测” | 应真实访问内容 API 或健康检查接口，并更新状态；不能只刷新本地配置元数据 |
| PS-013 | P1 | 状态数量一致性 | 在各种配置与筛选状态下比较标签数量和 DOM 行数 | “全部/正常/异常”计数与列表行数完全一致 |
| PS-014 | P0 | 重启持久化 | 完成新增、重命名和切换后关闭并重启应用 | 当前配置、其他配置、重命名结果和站点数量保持一致 |
| PS-015 | P1 | 控制台质量 | 执行完整流程 | 无 pageerror；无未处理 Promise；无 Vue key、事件或 IPC 错误 |
| PS-016 | P0 | 多仓索引导入 | 导入包含 `urls` 的多仓地址 | 自动展开下级配置；至少一个成功时整体可用；失败线路被隔离 |
| PS-017 | P0 | 多仓名称保留 | 查看导入后的配置列表 | 使用仓库条目原始名称，不统一变成“默认配置”或父级名称 |
| PS-018 | P0 | 多仓切换 | 切换任一成功导入的子配置 | 当前配置、站点列表和启用状态同步，始终只有一个启用配置 |
| PS-019 | P0 | 多仓重启恢复 | 切换子配置后关闭并重启应用 | 当前子配置名称和启用状态保持不变 |
| PS-020 | P0 | 重复 siteKey 隔离 | 两个子配置包含相同 `siteKey`，执行全部配置搜索 | 两个来源使用独立配置引用，详情和播放不会串到另一个配置 |

## 判定原则

- **通过**：界面结果、存储结果和真实网络状态一致。
- **失败**：功能不可用、数据错误、状态误报、永久 loading、配置丢失。
- **产品缺口**：当前界面没有入口完成必须的管理动作，例如无法删除当前配置。
- **状态误报**：仅依据运行时兼容性显示“正常”，但未验证内容接口是否可访问。
