## 2. 项目背景

当前 FongMi macOS 已具备播放源配置、首页、片库、搜索、详情、收藏、历史、内置播放器、mpv 兼容播放、CatVod Node 服务和多种 Provider 运行时等能力。

现阶段主要问题不是功能数量不足，而是产品结构过多地按照内部技术实现组织，普通用户需要理解播放源、配置源、CatVod、Provider、运行时、播放器内核、Cookie、Token、代理等概念，才能完成基本使用。

普通用户真正关心的是：

1. 是否能快速找到想看的影片；
2. 点击后是否能直接播放；
3. 网盘内容是否已经登录；
4. 播放失败时应用能否自动切换可用方式；
5. 是否可以记住进度并继续观看。

因此，本轮重构重点不是继续增加技术配置，而是将现有能力重新包装成面向普通用户的产品流程。

## 3. 当前问题概述

### 3.1 播放源和设置职责混乱

当前“播放源”页面主要负责选择来源，而以下功能又位于设置页面：

- 配置导入和切换；
- 播放源重新检测；
- CatVod 服务启动、停止、重启、更新和回滚；
- 配置中心入口；
- Provider 替代注册表；
- 运行时、端口、日志和内核信息。

从技术结构看这些功能可以拆分，但从用户视角看，它们都属于“内容来源是否可用”的同一个任务，当前拆分增加了理解成本。

### 3.2 设置页面暴露过多技术信息

普通用户不需要主动理解或修改：

- `index.js.md5` 地址；
- CatVod Node 服务；
- 启动阶段远程访问策略；
- Provider 注册表；
- Electron、Chromium、Node.js 版本；
- 本地端口、运行时类型和能力统计。

这些内容应保留用于调试和运维，但不应出现在普通设置的主流程中。

### 3.3 网盘扫码登录步骤过多

当前网盘登录依赖外部配置中心，典型流程包括：

1. 进入设置；
2. 找到 CatVod 服务；
3. 启动服务；
4. 打开配置中心；
5. 进入网盘登录；
6. 选择对应网盘；
7. 生成二维码；
8. 使用手机扫码；
9. 再次手动点击确认或轮询。

该流程过于复杂，应收敛为应用内“一键扫码登录—自动确认—自动继续播放”。

### 3.4 搜索体验与实际能力不一致

当前选中的“至臻”来源直接搜索“庆余年”可以正常返回《庆余年 第一季》和《庆余年 第二季》，说明当前来源的搜索接口可用。

但界面默认执行“全部配置源”搜索，后台需要遍历多个历史配置和大量异常站点。当前质量记录中存在大量静态不兼容、搜索降级、超时、规则缺失和返回异常内容的来源，导致：

- 当前可用来源未获得最高优先级；
- 搜索等待时间过长；
- 用户感知为“搜索不到”；
- 空结果时无法判断是没有内容还是来源失败；
- 搜索结果没有真正增量展示。

### 3.5 片库分类与来源不匹配

当前片库分类直接继承当前来源返回的分类，不同来源的分类名称、分类 ID、粒度和内容范围不统一，例如：

- 电影、最新电影、高清电影；
- 连续剧、电视剧、国产剧；
- 动画、动漫、国漫；
- 登录入口、配置入口、工具、直播和文件夹。

同时页面又叠加本地地区、年份和“热门”排序，部分筛选没有可靠数据依据，容易出现分类名称与实际内容不一致。

### 3.6 播放器兼容策略不透明

当前夸克线路可能返回 MP4/H.264/AAC 等常规媒体，但媒体地址依赖 Cookie、Referer、User-Agent、Range 和 206 分段响应。日志中出现多次 `proxy.chunk.download.incomplete`，主要风险可能来自分片、代理和请求头，而不是编码格式本身。

当前产品将内置播放器失败、媒体地址异常、网盘登录失效和播放源失效混合处理，用户只能看到“不兼容”或需要手动切换外部播放。

### 3.7 首页首屏只展示单一推荐

当前首页取首页结果第一条作为大图，其余内容进入网格。首屏无法展示多种推荐，也无法体现最近热播、热门电影或电视剧的丰富性。

## 4. 产品目标与原则

### 4.1 核心产品目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G-01 | 减少首次配置步骤 | 普通用户导入配置后即可浏览和搜索，不需要手动启动内部服务 |
| G-02 | 提高搜索命中速度 | 当前可用来源优先返回，首批结果不等待全部来源完成 |
| G-03 | 提高播放成功率 | Web 内核失败后自动切换高兼容播放器，不要求用户理解播放器类型 |
| G-04 | 简化网盘登录 | 从多页面、多步骤操作缩短为应用内扫码和自动确认 |
| G-05 | 统一片库分类 | 用户看到稳定、可理解的分类，来源原始分类作为补充 |
| G-06 | 提升首页内容丰富度 | 首页首屏支持多条推荐轮播，优先展示最近热播电影和电视剧 |
| G-07 | 降低技术认知负担 | 普通设置不展示 Node、Provider、端口、md5、运行时等技术概念 |

### 4.2 产品设计原则

1. **用户任务优先**：页面按“找片、看片、登录、管理来源”组织，而不是按内部模块组织。
2. **默认自动化**：能自动检测、自动重试、自动切换的功能，不要求用户手动选择。
3. **渐进式披露**：普通用户只看到必要设置，技术参数统一进入高级设置。
4. **结果优先**：优先显示“可用、已登录、可以播放”，技术细节仅在故障排查时展示。
5. **失败可恢复**：播放或登录失败时，直接提供当前场景下可执行的下一步。
6. **状态可追踪**：所有功能实现、测试和验收均在配套任务文档中持续更新。

### 4.3 非目标

本轮暂不以以下内容为主要目标：

- 重写全部播放源运行时；
- 追求最小安装包；
- 建设通用媒体资源平台；
- 为普通用户提供全部底层技术参数；
- 首期完成复杂的全量跨源内容推荐算法；
- 首期完成所有网盘类型的统一文件管理器。

## 5. 目标用户流程

### 5.1 首次使用

```text
启动应用
→ 应用自动启动必要服务
→ 粘贴或导入一个配置地址
→ 自动识别、检测并启用可用来源
→ 进入首页
```

普通用户不需要手动设置 CatVod 地址、端口、Provider 或运行时。

### 5.2 搜索与播放

```text
输入片名
→ 当前来源优先搜索
→ 健康来源补充搜索
→ 首批结果立即展示
→ 用户选择影片
→ 系统自动选择推荐线路
→ 内置播放
→ 必要时自动切换高兼容播放器
```

### 5.3 网盘内容播放

```text
用户点击网盘内容
→ 检查对应网盘登录状态
→ 已登录：直接解析播放
→ 未登录或过期：弹出扫码登录
→ 自动轮询登录结果
→ 登录成功后自动继续刚才的播放
```

### 5.4 播放失败恢复

```text
内置播放器失败
→ 自动切换高兼容播放器
→ 仍失败：尝试同影片其他线路或其他来源
→ 最终失败：展示明确原因和可执行操作
```

| 首页 | 最近热播、推荐轮播、继续观看、快捷入口 | 服务配置和技术检测 |

  - 失败次数。

- **优先级**：P0
- **状态**：已完成

### RQ-PLY-005 外部播放器兜底

- **优先级**：P1
- **状态**：已完成
- 仅在两层应用内播放器及备用线路/来源均失败后，提供 IINA、VLC 或系统默认播放器等外部打开方式。

- **完成情况**：外部打开由主进程固定 IPC 执行，不经过 shell 字符串拼接；仅允许 HTTP/HTTPS 媒体。需要 Cookie、Authorization、Referer 或其他专用请求头的受保护媒体不会把凭据交给外部进程，而是提示继续使用应用内播放器或更换线路。

### RQ-PLY-006 失败后自动换源

- **优先级**：P1
- **状态**：已完成
- **完成情况**：播放地址解析失败、地址过期、请求头或 Range 异常、线路不可用及准备超时时，先按稳定/原画偏好自动尝试同一集的其他线路；线路耗尽后使用标准化标题搜索其他来源，校验季、年份和内容类型，并按剧集名称或相同集数位置恢复，保持播放进度。已尝试线路和来源会被记录以避免循环；登录失效仍优先进入扫码登录。
- 当前线路失败后，可按用户设置自动尝试同影片的其他线路或来源。
- 自动换源前后应保持片名、季、集和播放进度上下文。

### RQ-PLY-007 高兼容播放器窗口与分发

- **优先级**：P0
- **状态**：实施中
- **当前完成情况**：Web 兼容的受保护夸克 MP4/HLS 已不再默认进入独立 mpv 窗口，而是通过主进程媒体会话在应用内 ArtPlayer 完成真实 4K 播放、暂停、绝对跳转、恢复和多集切换；ArtPlayer 不再对不透明媒体协议强制启用网页跨域模式。真正无法由 Chromium 解码的 MKV、FLV、MPEG-TS、HEVC 特殊封装等仍会进入高兼容播放器或外部兜底。剩余缺口是非 Web 格式的统一窗口体验、进程控制，以及 x64/arm64 安装包中的一致分发和实机验证。
- 高兼容播放器应具备可控的窗口体验，不要求用户面对额外技术窗口或不可解释的进程行为。
- x64 和 arm64 安装包均应具备一致的高兼容播放能力。
- 需要覆盖开始播放、连续播放、暂停恢复、绝对跳转、倍速、多集切换和退出清理。

  - 换一条线路；
  - 查找其他来源；
  - 检查并修复内容来源；
  - 重试。

### RQ-FBK-003 质量状态不误伤

- **优先级**：P0
- **状态**：已完成
- **完成情况**：搜索、播放和总体成功指标已拆分记录；一次搜索超时、首页空结果、网络失败、登录失效或播放器内核问题只降低排序或保持来源状态，不会永久隐藏来源。只有静态不兼容及确定性的详情、播放、媒体链路失败才进入默认阻断。旧数据库启动时自动补充新的质量指标字段。
- 搜索超时、首页无内容、一次网络失败或播放器内核不兼容，不得直接永久隐藏整个来源。
- 只有确定性的静态不兼容、详情缺失、播放地址永久失效等情况，才进入默认隐藏或阻断状态。

## 7.9 数据、安全与隐私

### RQ-SEC-001 凭据安全存储

- **优先级**：P0
- **状态**：已完成
- Cookie、Token、账号密码等凭据继续采用安全存储或加密存储。
- 不允许通过通用设置接口读取或修改受保护凭据。
- **完成情况**：账号页面只通过固定 IPC 获取配置状态、登录状态和二维码，不返回凭据字段；CatVod Profile 仍由主进程加密存储，通用 Renderer 设置接口继续禁止访问受保护键。

### RQ-SEC-002 日志脱敏

- **优先级**：P0
- **状态**：已完成
- **完成情况**：建立集中式日志脱敏模块，统一覆盖 Authorization、Cookie、Set-Cookie、Token、访问密钥、账号、密码、URL Basic Auth、敏感查询参数、分享口令和中文提取码。CatVod 服务日志、来源适配器错误、CatVod HTTP 响应摘要、CatOpen 子进程、主进程启动错误、Renderer IPC 和 CLI 输出均已接入；结构化对象和错误堆栈也会递归脱敏。发布前安全审计扫描 29 份运行日志及 JSON、Markdown、文本报告，21 项安全检查全部通过，未发现明文凭据。
- 日志不得保存完整 Cookie、Token、账号、密码、分享口令和带敏感查询参数的完整 URL。

### RQ-SEC-003 登录任务生命周期

- **优先级**：P1
- **状态**：已完成
- 二维码登录任务必须支持过期、取消和清理。
- 应避免重复轮询、任务泄漏和页面关闭后继续无效请求。
- **完成情况**：登录任务支持过期、重新生成和主动取消；关闭弹窗、关闭页面或重新生成二维码时会停止轮询并清理旧任务，成功和终态不会继续发送无效请求。

## 8. 非功能需求

### 8.1 性能

1. 当前来源搜索应优先发起。
2. 搜索结果必须增量显示，不等待全部来源结束。
3. 单来源搜索和播放解析设置明确超时。
4. 不应默认遍历全部历史配置中的全部异常来源。
5. 首页轮播资源应懒加载和缓存，避免阻塞主界面。

### 8.2 稳定性

1. 单来源失败不得阻塞整体搜索。
2. 单条线路失败不得直接判定整部影片或整个来源失效。
3. CatVod 服务异常时提供自动恢复。
4. 播放切换内核时不得丢失应用主窗口状态。

### 8.3 可维护性

1. 用户界面状态与底层服务状态分离。
2. 技术配置统一进入高级设置。
3. 需求、任务、测试和实现使用固定编号关联。
4. 每次实现必须同步更新配套任务文档。

### 8.4 可测试性

1. 搜索、登录、播放、分类映射和轮播均应具备自动化测试。
2. 真实源测试与模拟测试分开记录。
3. 关键链路需要端到端测试：搜索—详情—登录—播放—续播。

## 10. 总体验收标准

完成本轮重构后，应满足：

1. 普通用户无需理解 CatVod、Provider、运行时或播放器内核即可使用。
2. 导入一个有效配置后，应用自动完成必要服务启动和来源检测。
3. 搜索当前可用来源时，可以快速返回结果。
4. 搜索结果可以增量展示，并可继续搜索更多来源。
5. 播放夸克内容时，未登录可直接扫码，登录后自动继续。
6. 内置播放器失败后自动切换高兼容播放器。
7. 播放器不兼容不会错误地永久屏蔽整个来源。
8. 片库分类与当前来源内容基本匹配，工具和登录项不会进入影视分类。
9. 首页首屏展示多条最近热播电影或电视剧轮播。
10. 普通设置不再展示 md5、端口、Provider、Node、Electron 等技术项。
11. 每项功能的开发状态、测试结果和验收结论均可在任务文档中追踪。
