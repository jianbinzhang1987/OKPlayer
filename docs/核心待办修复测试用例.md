# 3. 真实代理媒体 Range、拖动和动态端口

## 3.1 本地受控媒体 Fixture

Fixture 提供：

- 支持 Range 的 MP4/二进制媒体端点；
- HLS 主清单、子清单、分片、密钥、字幕端点；
- 必须携带 Cookie、Referer、User-Agent 的受保护端点；
- 可切换端口的 CatVod 代理端点；
- 可模拟 401/403、404、500、连接中断和延迟的端点。

## 3.2 测试用例

| 编号 | 用例 | 操作 | 预期结果 |
|---|---|---|---|
| MEDIA-001 | MP4 首次加载 | 请求完整媒体 | 正确返回 200、Content-Type 和长度 |
| MEDIA-002 | 单段 Range | 请求 `bytes=100-199` | 上游收到 Range；返回 206 和正确 Content-Range |
| MEDIA-003 | 连续拖动 | 依次请求多个不连续 Range | 每次 Range 独立透传，无缓存错位 |
| MEDIA-004 | HEAD 请求 | 播放器探测媒体 | Header 正确返回，不下载正文 |
| MEDIA-005 | 受保护 Header | 媒体要求 Cookie/Referer | Header 仅由主进程附加，Renderer URL 不含凭据 |
| MEDIA-006 | HLS 主子清单 | 请求主清单后请求子清单 | 所有 URL 重写为 `fongmi-media://` |
| MEDIA-007 | HLS 分片与密钥 | 请求分片和 AES Key | 保留正确父 URL、Header 和 Range |
| MEDIA-008 | 动态端口切换 | CatVod 从端口 A 重启到端口 B | 新准备会话使用 B；旧稳定 URL可按策略恢复或明确失败 |
| MEDIA-009 | 服务重启后续播 | 保存进度后重启 CatVod | 重新准备播放会话并从原进度继续 |
| MEDIA-010 | 凭据失效 | 上游返回 401/403 且属于网盘上下文 | 转换为鉴权错误，不降低来源质量 |
| MEDIA-011 | 资源失效 | 上游返回 404/410 | 标记线路失效，允许换线路/换来源 |
| MEDIA-012 | Range 响应异常 | 上游忽略 Range 返回 200 | 客户端不伪造 206，播放器获得可诊断结果 |
| MEDIA-013 | 会话过期 | TTL 后访问稳定 URL | 返回明确 404，不访问未知上游 |
| MEDIA-014 | 多会话隔离 | 两个媒体使用不同 Cookie | 请求头不串用，不发生凭据泄漏 |

# 4. 故障注入和数据恢复

| 编号 | 用例 | 注入方式 | 预期结果 |
|---|---|---|---|
| REC-001 | 当前脚本损坏 | 修改当前版本脚本内容 | 校验失败后从可信源重新下载或回退 |
| REC-002 | manifest JSON 损坏 | 写入无效 JSON | 归档损坏文件并重建，不静默覆盖稳定脚本 |
| REC-003 | 当前版本目录缺失 | 删除版本目录 | 启动时自动修复或给出明确错误 |
| REC-004 | 候选版本崩溃 | Fixture 候选启动即退出 | 候选不激活，稳定版本继续运行 |
| REC-005 | 活动服务异常退出 | 播放/浏览期间结束 Utility Process | 自动重启且动态端口更新 |
| REC-006 | 长时网络中断 | 下载和媒体请求超时 | 有限重试，可取消，不产生死循环 |
| REC-007 | 登录任务中断 | 登录等待中停止 CatVod | 任务转错误/取消，重启后可重新登录 |
| REC-008 | 应用强制退出 | 存在会话、隐藏窗口和等待扫码任务 | 下次启动端口可用，无永久锁和脏任务；已保存网盘凭据保持不变 |
| REC-009 | SQLite 非数据库文件 | 用普通文本替代数据库 | 原文件归档，提示恢复，不静默清空 |
| REC-010 | SQLite 部分表损坏 | 缺表或列 | 可迁移的自动迁移；不可迁移的进入只读/恢复提示 |
| REC-011 | 自动备份 | 正常关闭或关键写入前 | 保留有限数量数据库备份 |
| REC-012 | 从备份恢复 | 主库损坏且备份有效 | 自动或显式恢复配置、历史、收藏和设置 |
| REC-013 | 恢复失败 | 主库和备份都损坏 | 明确提示并保留原文件，禁止静默覆盖 |

Electron E2E 重点验证 REC-004、REC-005、REC-007、REC-008、REC-012。

1. 先补齐 PAN、MEDIA、REC 的单元与集成测试；
2. 修复对应服务、协议、存储和 Renderer 状态机；
3. 补齐 FOLDER、SUB、DAN 的组件和页面测试；

5. 执行专项测试、全量测试、类型检查和生产构建；
6. 构建 Electron 测试包并执行新 E2E；
7. 最后执行真实账号、真实网盘、Apple Silicon 和公网样本验收。

自动化闸门：

- 专项测试 100% 通过；
- 全量测试无回归；
- TypeScript 类型检查通过；
- Renderer 与 Desktop 生产构建通过；
- Electron E2E 无控制台错误、页面错误和非预期请求失败；
- 日志扫描无 Cookie、Token、账号密码和分享码泄露。

环境依赖项如果因缺少真实账号或设备不能执行，必须在报告中标记“未执行”，不得以 Fixture 通过替代真实验收。
